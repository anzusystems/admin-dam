planned
===

Toolchain and API upgrade on top of 2.x: Vite 8, TypeScript 6, every api call on the `@anzusystems/common-admin` labs helpers, a vitest suite, a Playwright e2e suite in place of Cypress, and a long list of upload queue, list and start-up fixes. Items marked **Breaking** need action before or after deploying.

### Requirements
- **Node `^22.22.2 || ^24.15.0 || >=26.0.0`** (was `^20.19.0 || >=22.12.0`), in `e2e/` as well — `engines` was the last admin still on the old range
- **`@anzusystems/common-admin` 1.47.0** — the labs api helpers, the shared user and permission group screens, the eslint config and its `anzu/*` rules. Pinned to the beta build `1.47.0-beta.dev-1790143991` until 1.47.0 is released
- **Local docker image `anzusystems/node:4.2.0-node24-nginx-browsers`** (from `4.1.0`); the first `bin/docker-compose build` after pulling fetches a new layer set

### Added
- **One page for the whole account, at `/users-new`.** The same person was edited in two places — `/users` for licences, licence groups, ext systems and distribution services, `/anzu-users` for roles, permission groups and grants — though they are one row and `PUT /adm/users/{id}` takes all of it; the new page saves both halves in one call. **Permission groups** from the shared common-admin screens are at `/permission-groups-new`. Both sit beside the originals, in the menu only with debug features on, until parity is confirmed; then `/users-new` takes `/users` over
- **A vitest suite** — the upload queue, list and start-up fixes below are covered by tests, and a route smoke test resolves all 69 generated routes to their own record rather than the catch-all, checks the declared and runtime name sets against each other in both directions and asserts every route has a component. Importing `vue-router/auto-routes` pulls in every page with its stores, api clients and composables, so anything that throws during module evaluation fails here; without `src/typed-router.d.ts` the suite does not load, and `yarn ci` runs `generate:dts` first. `@vitest/ui` and `yarn test:ui` as in the other admins
- **`bin/test --unit` and `--e2e`.** Without a switch it runs vitest first — no environment or browser needed, the result is on screen in seconds — then Playwright; passing both is an error, and a failing vitest run makes the script exit non-zero at the end instead of hiding behind the e2e run
- **The environment's label sits in front of the browser title** — `DEVEL: ADAM`, `STAGE: ADAM`; production sets no label, so its title is unchanged. It comes from `APP_LABEL`; a config that predates the key shows no label instead of crashing
- **The page reloads itself when a new version is deployed.** `ASystemBar` already polled `config.json` for a new `appVersion` but only lit the bar; the router guard now parks the pending navigation and reloads, a `beforeunload` veto releases the navigation after three seconds instead of leaving it hanging, and a 30-second stamp in `sessionStorage` stops a reload that does not take from looping. Same behaviour as the other five admins

### Changed
- **Every api call moved onto the common-admin labs helpers** — `useApiRequest`, `useApiFetchList`, `useApiFetchByIds`, `useApiFetchListBatch`, `useApiCommand`, `useApiFetchItems`; the `src/services/api/` functions now fail an import. The rename is mechanical and the compiler found all of it; what a response means changed in ways it does not point at:
  - a failure arrives as its own class — `AnzuApiAxiosError`, `AnzuApiTimeoutError`, `AnzuApiResponseCodeError` — instead of `AnzuFatalError` for everything, so a branch on `isAnzuApiAxiosError` can now be taken where it never was
  - a request the user superseded (another keystroke in an autocomplete, a route change mid-load) is an `AnzuApiCancelledError` and no longer raises an alert
  - a 204 answers `undefined` instead of `null`, and on a list or by-ids read `[]` — a list read used to throw `AnzuApiResponseCodeError` unless it asked for `optionalBody`, and none did. Nothing in scope answers 204 today
  - a 202 with no body resolves instead of rejecting as fatal
  - a list response is shape-checked; a malformed one is a thrown, logged error naming the url instead of `undefined` typed as an array failing somewhere unrelated later
  - `anzu/prefer-api-fetch-items` is on as an error: a `useApiRequest` typed as a list has to be `useApiFetchItems`; a call that really reads the envelope's metadata takes a per-line disable with the reason
- **User form**: creating an account asks for the same fields as editing one — it used to need only an id and an e-mail, while name, full name and avatar were required on edit alone; how strict the form is is now a property of the system. The avatar colour is validated by its shape rather than its length (`#GGGGGG` passed the form and failed on the server)
- **Sentry collects through `dataCollection` instead of the deprecated `sendDefaultPii`** (gone in SDK v11). The four categories are named one by one, even where they match today's defaults, so a default moving in v11 cannot change what is sent. `profilesSampleRate` is dropped — it never did anything without a browser profiling integration. Since `@sentry/vue` 10.75.2 `urlQueryParams` is actually applied to urls: query params whose name contains `auth`, `token`, `session`, `key`, `sid`, `identity` and similar arrive as `[Filtered]` (substring match — `keyword` too)
- **Components declare their model with `defineModel`** instead of a `modelValue` prop plus an `update:modelValue` emit; prop, emit, passthrough handler and `computed({ get, set })` collapse into one writable ref, same behaviour. A model that accepts `null` but only ever emits a real value keeps the old form, with a comment why — `defineModel` has one type for both directions
- **Lint and test toolchain on the setup the other admins run**
  - the shared eslint and stylelint config — the ones blog, forum and inhouse run — both with zero findings. `anzu-local/valid-route-name` is the stronger variant: the old one resolved the declaration through `process.cwd()` and checked nothing when run from a subdirectory. `@typescript-eslint/no-explicit-any` stays an error, and the two `any` casts it could not see in `<template>` blocks (`currentUser as any`, `el as any`) are typed in the script — the current user narrowed to `AnzuUserMinimal`
  - five stricter vue rules — `no-undef-components`, `attribute-hyphenation`, `v-on-event-hyphenation`, `custom-event-name-casing`, `define-emits-declaration`. The config reads the registered components from the Vuetify and common-admin `.d.ts` files and names the ones registered elsewhere (`Acl`, `GMap*`)
  - the file-based routing options live in `routerPages.config.mts`, byte for byte the same in all six admins, so vitest builds the same route table as the app
  - `.vscode/settings.json` and `extensions.json` are shared and tracked — oxfmt as formatter, fix-on-save for oxlint then eslint, stylelint over `scss` and `vue`, the workspace TypeScript; the rest of `.vscode/` stays ignored
- **The e2e suite is Playwright instead of Cypress** ([#273](https://github.com/anzusystems/admin-dam/pull/273)) — 61 specs in `e2e/`, a yarn project of its own on the shared lint and format setup (`yarn ci` = `lint:tsc`, `format:check`, `lint:oxlint`) and on TypeScript `~7.0.2`, the native compiler: there are no `.vue` files in it, and Playwright transpiles the suite itself. It targets `local`, `devel` or `staging` (`ADAM_ENV`, `bin/test -e`), reads its credentials from `e2e/.env.<env>` and downloads the media fixtures in `globalSetup`. `bin/test` drives it the way admin-cms does — `--unit` / `--e2e`, `-f` and `-i` for grep and grep-invert, `-b`, `--headed`, `--ui`, `--spec`, anything after `--` passed through. **Breaking for every developer:** the Cypress `e2e/config/<env>.ts` files are gone; copy `e2e/.env.dist` to `e2e/.env.<env>` and fill it in, as `e2e/README.md` describes, which also replaces `README-TEST.md`
- **Sentry build setup from common-admin** — `anzuSentry({ project: 'anzu-admin-dam' })` from `@anzusystems/common-admin/vite` replaces the `sentryVitePlugin` block, the same call in all six admins. Frames from common-admin resolve to its `.vue` and `.ts` sources instead of the minified `dist/common-admin.js` (its source maps are chained into ours); maps stay `hidden` and are deleted after the upload, now from the resolved `build.outDir`. A missing `SENTRY_AUTH_TOKEN` or a failed upload fails the build instead of a warning
- **Dependencies — major**
  - **`vite` `^7.3.6` → `^8.3.0`** (Rolldown instead of Rollup). The three deprecations it reports are cleared: `rollupOptions` → `rolldownOptions`, `manualChunks` → `codeSplitting.groups` (Rolldown ignores `manualChunks` once `codeSplitting` is present, so not cosmetic), and the extensionless imports between root configs that `configLoader: 'native'` does not resolve — hence the `.mts` config files. Chunk names are identical before and after
  - **`typescript` `5.9.3` → `~6.0.3`** — `strict` on by default; `e2e/` is on `~7.0.2`, see the Playwright suite above
  - **`@vueuse/core` / `@vueuse/integrations` `14.4.0` → `15.0.0`**, exact pins, no code changes: this app uses `useDebounceFn` (eighteen datatable search fields), `onKeyUp` (arrow keys on the two asset lists) and `useClipboard` (asset-slot row), none touched by v15. The flipped `useThrottleFn` `trailing` default would have made a double-click on `ADatatablePagination`'s next or prev step two pages — that is common-admin's, and the pinned build passes `trailing: false` on all four buttons
  - also major: `postcss-html` `1` → `2` and `stylelint-config-recommended-vue` `1` → `2` (bringing `stylelint-config-html` and `stylelint-config-recommended` in as explicit dependencies); `dotenv` `17` → `18`, whose removed preload and `.env.vault` support nothing here uses
- **Dependencies — minor and patch**: `@sentry/vue` `10.75.2`, `@tiptap/*` `3.31.3`, `vuetify` `4.2.1`, `vue` `3.5.43`, `vue-router` `5.3.1`, `vue-i18n` `11.4.12`, `pinia` `4.0.3`, `axios` `1.20.0`, `uuid` `14.0.2`, `@intlify/unplugin-vue-i18n` `11.2.5`, `eslint` `10.11.0`, `eslint-plugin-vue` `10.11.0`, `oxlint` / `eslint-plugin-oxlint` `1.85.0`, `oxfmt` `0.70.0`, `vue-tsc` / `@vue/language-server` `3.3.11`, `@vitejs/plugin-vue` `6.0.9`, `sass` `1.105.0`, `stylelint` `17.15.0`, `postcss` `8.5.28`, `browserslist` `4.29.0`, `unplugin` `3.4.0`, `@tsconfig/node24` `24.0.5`, `@types/node` `24.13.6`. New: `vitest` / `@vitest/ui` `5.0.1`, `happy-dom` `20.14.5`, and `dayjs` `1.11.23`, which `src/` used while it resolved only through a transitive copy. `@stylistic/eslint-plugin` and the Cypress packages (`cypress`, `@cypress/grep`, `cypress-downloadfile`, `cypress-mochawesome-reporter`) dropped; `@playwright/test` `1.63.0` in `e2e/`

### Removed
- **Our own error logging** — `ErrorHandlerApiService`, `createLog`, its test and the `apiLogError` config; Sentry runs everywhere
- **`dam.imageUrl`** — delivered by the config and never read since the initial commit
- **The "Nové heslo" field on the user form.** Nothing ever read it: `plainPassword` appears in no PHP in `core-dam` or `core-dam-bundle`, and the endpoint drops unknown keys. Setting a password from the admin would be a new backend feature, not a repair
- **`lint:browserslist`** and `.browserslistrc`. The check failed `ci` once `caniuse-lite` was six months stale while guarding nothing: `supports css-cascade-layers` has a fixed minimum per engine, and nothing reads the file — the query is written out in `vite.config.mts`. `browserslist:update` stays as a manual script

### Fixed
- **Upload queue** ([#86567](https://dev.azure.com/petitpress/Anzu/_workitems/edit/86567))
  - cancelling stops an upload where it stands — between chunks, while the next one is read off disk, during a retry back-off — not only while a request is on the wire. The opening and finishing requests are not cancelled themselves, and the asset an upload already created stays on the server; only the queue item goes
  - removing an item while it uploads tears it down like stopping it, instead of posting chunks to a deleted asset and reporting a failure the user caused, and refills the freed slot at once
  - the queue keeps to its two parallel uploads — it started two more whenever a slot came free — and a failed external-provider import no longer holds a slot for the rest of the session
  - two uploads into different slots of one asset no longer settle each other, a second upload into the same slot shows its progress again, and two files of the same name no longer share a key, so removing one no longer makes another disappear
  - a retried chunk no longer reports a negative speed that collapsed the adaptive chunk size to its minimum just as the connection was worst
  - dropping a folder offers all of it — browsers answer the directory reader in batches, so three hundred files quietly became the first hundred — and an entry that is neither file nor folder no longer leaves the drop waiting for ever
  - the file size limit accepts a file exactly at the limit, as the backend does (`size <= sizeLimit`); the `*` and `.extension` forms of the limit map are applied the right way round and `.extension` is matched against the file name. The checks live in `fileValidation.ts`
  - the notification fallback: a stopped or cleared item no longer leaves its self-rescheduling timer polling for minutes; when it gives up it says why (on the warning icon) and the row can be cancelled; a transient failure no longer ends the retry chain; it no longer reports a slot finished on the strength of the asset's main file when that is a different file — so a slot upload usually needs its notification; and the library's fallback follows its configuration, except for the external-provider import, whose notification can arrive before its ids
  - an upload that finishes without its metadata says so on the row, offers refresh after twenty seconds at the latest, and refresh fetches the missing metadata rather than only the file status; the bulk save no longer skips such an item in silence
  - a file notification no longer fails an asset picked for mass edit before it had a file — only the processed handler acts on such a row, bringing status and preview
- **Mass edit and bulk save**: the bulk metadata save sends only what the form edits — it always sent `mainFileInternal`, `mainFileOverrideInternal` and `ttsAudio` as `false`, so changing one keyword on a TTS asset turned TTS off. A tile stays highlighted only while its asset is in the mass edit queue, in both lists; the dialog's cancel and delete, the external provider's bin and the import used to leave it highlighted. Selecting or importing exactly the maximum no longer warns or is refused. Metadata for a selection that cannot be loaded no longer waits for ever
- **Lists**: a page that fails to load is retried rather than skipped; a list restarted from page one (a filter change) discards answers from the requests it replaced, so the older of two filter changes no longer wins; scrolls are served one at a time and a pending one is replayed unless the list was replaced meanwhile; each request gets a pagination object of its own, since the library overwrites the one it is given
- **Asset detail**: only the newest request may answer — counted in the detail store, shared by the list, the queue dialog and the arrow keys — so a held-down arrow key or a quick click no longer lands an older asset on top of the current one. A failed fetch no longer leaves a spinner or opens the fullscreen dialog on nothing; the five-second cache no longer holds a failed request, and a failure clears the detail rather than leaving the panel offering to save the previous asset. The slot panel recovers from a failed load, and making a file public or private for an asset type without a matching branch fails instead of loading for ever
- **The slot remove dialog is titled "Odstrániť?"** — it asked for the undefined `common.modal.system.confirmDelete` and showed the raw key
- **Start-up and sign-in**
  - a start-up failure that says nothing about the user leads to a new error page with a retry instead of the sign-in screen; a link to an asset the server answers 404 or 403 for leads to not-found. A sign-in the SSO already refused is answered before the start-up fetches anything, and it waits for both of its requests. Still out of reach: the current-user request answers `undefined` for every failure, so an outage of that one endpoint still looks like a sign-in problem
  - a failing public configuration no longer leaves a blank page — it was awaited in the router guard with nothing to catch it
  - the sign-in button shows it is working and a second submit starts no second request; a successful sign-in reloads the page, since signing in as somebody else kept the previous user's identity, permissions and configuration until a manual reload
- **Client and auth**
  - `damClient()`, called on every request and once per chunk, no longer registers another request and response interceptor on the shared instance each time. Its `timeoutBase` and `onUploadProgress` arguments only ever reached the first call, so they never worked; chunk uploads pass their longer timeout in the request config
  - a request waiting for a token refresh is released in the right order — the in-flight flag came down in a `.finally`, after the released requests' continuations, so one of them could join a queue nobody would flush again
  - notification listeners are registered once instead of once per start-up, and reading the auth cookies no longer leaks a VueUse `useCookies()` instance and change listener per call outside an effect scope
- **Locale messages are precompiled.** `include: './src/locales/**.json'` matched nothing (`**` inside a path segment degrades to `*`), so the messages shipped as raw JSON and were compiled in the browser on every load. The glob is `'./src/locales/**/*.json'` — the documented `'./src/locales/**'` also matches `sk.ts` and silently drops its imports with a green build
- **`bin/*` wrappers**
  - `bin/lint` and `bin/test` no longer report success whichever way they ran — `bin/docker-compose` ended in a cleanup block that exited 0 and discarded the compose command's status; it is captured before the cleanup and returned
  - `bin/test` exits 1 after rejecting an invalid `-e`, `-b` or unknown switch, and `-e` with no value no longer loops forever
  - `bin/build` no longer reports success after a failed install or build, and prints `Build ready` only when something is

### Deployment
- **`config.json.dist` no longer asks for `API_LOG_ERROR_ENABLED`, `API_LOG_ERROR_URL` and `DAM_IMAGE_URL`, and asks for `APP_LABEL`.** A deployment that supplies its own template — the petit deploy repository keeps a `config.json.cf.dist`, which already carries `appLabel` — can drop the `apiLogError` and `dam.imageUrl` keys and those variables once no version still reading them is a rollback target. Until then leave them: `apiLogError.enabled` sits in an unquoted position, so an unresolved token there is invalid json
- **`APP_LABEL` has to be defined in every environment, production included, where it is empty.** `replacetokens` leaves an unknown `#{APP_LABEL}#` in place rather than blanking it, so a missing variable would print the token into the title
